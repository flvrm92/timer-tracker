Electron 41.0.2 was chosen as the Phase 04 target per the following rationale (recorded in `phase-04-runtime-risks.md`):

- Electron 42 introduced a fresh-install behavior change that would complicate Phase 05 Store testing.
- As of 2026-05-08 the supported Electron stable lines are 40.x, 41.x, and 42.x; Electron 41 sits in the middle of that window, maximising support lifetime before Phase 05 completes.
- Electron team upgrade guidance recommended 41.0.2 as the preferred intermediate target from 33.x for this class of app.
- Electron 41.0.2 includes groundwork for MSIX auto-update, which Phase 05 will rely on.

## 2. Code and Configuration Changes Required

### 2.1 `package.json` changes

**Dependency bumps**

```diff
-  "electron": "^33.2.0",       // devDependencies
+  "electron": "41.0.2",

-  "sqlite3": "^5.1.7",         // dependencies
+  "sqlite3": "6.0.1",
```

Both are pinned exactly to prevent unintended patch bumps from changing native ABI requirements between CI runs.

**`node-abi` override (required)**

```json
"overrides": {
  "node-abi": "3.92.0"
}
```

`node-abi` is used by `@electron/rebuild` (pulled transitively by Forge `core-utils`) to map an Electron version to its V8/Node ABI number.  The version of `node-abi` that `@electron/rebuild@3.7.2` resolved without the override was `~3.75.0`, which only carried Electron ABI mappings up to Electron 37.x.  Without the override, `electron-forge package` fails with an ABI lookup error when targeting Electron 41.0.2 (ABI 145).  `node-abi@3.92.0` carries mappings through Electron 43.x.

### 2.2 Application code changes

**None.**

Electron 41 introduced no breaking changes that required edits to:

- `src/main/index.js` — BrowserWindow creation, security flags, menu wiring, IPC setup
- `src/main/ipcHandlers.js` — IPC channel registrations and database callbacks
- `src/infra/database.js` — sqlite3 callback-style API (unchanged between sqlite3 5.x and 6.x)
- `src/settings/preload.js` — contextBridge exposure
- `src/renderer/*` — all renderer pages
- `src/shared/*` — utilities and styles

The existing security posture (`nodeIntegration: false`, `contextIsolation: true`, preload sandbox, no `enableRemoteModule`) was already aligned with Electron 41 best practices.  No configuration relaxation was needed.

### 2.3 `package-lock.json`

Regenerated by `npm ci` after the `package.json` changes.  The lockfile now pins `sqlite3@6.0.1` and `node-abi@3.92.0` (via the override resolution).

## 3. sqlite3 6.0.1 Specifics

sqlite3 6.0.1 is API-compatible with 5.x at the JavaScript level used by this project (callback-based `Database`, `Statement`, `run`, `get`, `all`).  No application code changes were needed.

The native module is compiled by `@electron/rebuild` during `electron-forge package` / `make`.  The `plugin-auto-unpack-natives` plugin correctly unpacks `node_sqlite3.node` to `app.asar.unpacked/node_modules/sqlite3/build/Release/` so the packaged app can load it at runtime without ASAR extraction overhead.

## 5. Accepted Residual Warnings and Carry-Forwards

### 5.1 SSH `@electron/node-gyp` in lockfile (carry-forward)

`package-lock.json` contains a `git+ssh://git@github.com/electron/node-gyp.git` resolved URL at line 1398.  `npm ci` emits:

```
npm warn skipping integrity check for git dependency ssh://git@github.com/electron/node-gyp.git
```

**Root cause:** `@electron/rebuild@3.7.2` (pulled by `@electron-forge/core-utils@7.11.1`) declares `@electron/node-gyp` with a Git-hosted resolution rather than a published npm registry package.  This is not caused by `sqlite3` or any direct dependency.

**Impact:** Supply-chain hygiene risk only.  The dependency is a devDependency used solely during native module compilation by Forge; it is not shipped in the packaged application.  CI `npm ci` still produces a deterministic install because the commit hash is pinned in the lockfile.

**Resolution path:** Upgrading `@electron-forge/core-utils` to a version that depends on a published `@electron/node-gyp` package would eliminate the warning.  Deferred to Phase 05 when a Forge minor that resolves this becomes available and validated.

### 5.2 38 audit vulnerabilities (carry-forward)

All 38 reported vulnerabilities (6 low, 5 moderate, 27 high) are in transitive `devDependencies` of the Forge toolchain and Squirrel maker.  None are in the packaged application runtime path.  `npm audit --production` reports 0 issues.  Audit remediation is a Phase 05 task.

### 5.3 `[DEP0187] DeprecationWarning` during `npm run make`

Node.js emits one `DeprecationWarning` about `fs.existsSync` receiving an invalid argument type.  This originates in the Squirrel maker toolchain, not in application code.  It does not affect the produced artifacts.  Carry-forward to Phase 05.

### 5.4 Deprecated transitive packages

`npm ci` warns about `inflight`, `lodash.get`, `@npmcli/move-file`, `rimraf` (v2/v3), `glob` (v7/v8), and `boolean`.  All are transitive Forge toolchain dependencies.  None are application runtime dependencies.  Carry-forward to Phase 05.
